# Архітектура лабораторної роботи

## Призначення основних понять

- **Manifest** — файл опису проєкту та його залежностей. Він визначає метадані
  пакета, залежності й параметри середовища, але не є покроковою інструкцією
  для агента.
- **Skill** — набір спеціалізованих інструкцій (`SKILL.md`) для повторюваної
  задачі, можливо з ресурсами або скриптами. `SKILL.md` читається лише для
  команди, якій цей skill призначено.
- **Command** — окрема prompt-інструкція для запуску однієї сфокусованої дії.
- **Orchestrator** — команда, яка визначає послідовність етапів, передає між
  ними результати та зупиняє процес у разі помилки.

## Заплановані skills

| Skill | Призначення | Статус |
|---|---|---|
| `project-scaffold` | Створення структури Python-проєкту та програми Hello World | Описано, виконання не реалізовано |
| `build-and-test` | Створення скриптів складання й перевірки, запуск pytest і пакування PyInstaller | Описано, виконання не реалізовано |
| `github-actions` | Створення CI для Windows, Linux і macOS | Описано, виконання не реалізовано |

## Заплановані commands

| Command | Призначення | Статус |
|---|---|---|
| `git-init` | Підготовка Git-структури та робочої гілки; окремий skill не потрібен | Заплановано |
| `create-project` | Генерація файлів Python-проєкту | Заплановано |
| `create-build` | Генерація скриптів складання й перевірки | Заплановано |
| `create-actions` | Генерація конфігурації GitHub Actions | Заплановано |
| `check` | Перевірка створеного проєкту без редагування його коду чи конфігурації; окремий skill не потрібен | Заплановано |
| `init` | Оркестрація етапів у визначеному порядку | Заплановано |

## Потік даних між етапами

Етапи передаватимуть один одному такі дані:

1. **Параметри проєкту** — мова Python, варіант 2, використання `venv`,
   `pytest` і PyInstaller, підтримувані Windows, Linux та macOS, а також назви
   запланованих компонентів.
2. **Створені файли** — перелік нових або оновлених файлів, їх призначення та
   результати попередніх етапів. Уже наявні дані README, зокрема ПІБ і група,
   мають зберігатися. Пакування має створювати `dist/hello.exe` на Windows і
   `dist/hello` на Linux/macOS; ці результати не комітяться.
3. **Результати перевірок** — фактичні локальні результати запуску програми,
   `test_BasicAddition`, скриптів і зібраних файлів на відповідній ОС, а також
   окремі результати GitHub Actions. Зібрані файли зберігаються як артефакти
   GitHub Actions, а тимчасові файли перевірок мають бути виключені з Git.

Перед виконанням кожного етапу оркестратор має прочитати відповідний
prompt-файл. `SKILL.md` читається лише для команд, яким призначено skill;
`git-init` і `check` можуть працювати без окремого skill. Якщо потрібний
prompt-файл або призначений `SKILL.md` відсутній, етап не запускається, а
причина повідомляється користувачу.

## Зупинка при помилках

Якщо етап завершився помилкою, оркестратор зупиняє всі наступні етапи, зберігає
доступні результати та пояснює причину. Наступні етапи не можна позначати
успішними без їх фактичного виконання. Повторний запуск має бути безпечним:
коректні файли зберігаються, а конфігурація не дублюється.

## Гілки

- `develop` міститиме агента та інструкції лабораторної роботи.
- `feature/...` міститиме згенерований і перевірений проєкт.

## Поточний статус

Цей документ описує архітектуру та інструкції майбутніх skills. Skills уже
описані, але їх виконання, commands, програма та CI ще **не реалізовані**.
Скрипти складання, тести, пакування PyInstaller і GitHub Actions у поточному
етапі не створюються. Запланований
результат пакування — `dist/hello.exe` на Windows і `dist/hello` на
Linux/macOS; кожен файл має запускатися на відповідній ОС для перевірки
`Hello World` і зберігатися як артефакт GitHub Actions, але не комітитися.
